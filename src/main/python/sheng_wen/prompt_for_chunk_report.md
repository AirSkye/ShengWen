# ShengWen Agent 分块报告化呈现附加提示词

本任务已开启“结果美化”。在严格遵守分块基础提示词、前块衔接、状态协议、内容保真和详细度规则的基础上，再执行以下呈现约束。

## 通用呈现
- 不按视频类别套模板，按当前块的实际信息结构选择普通段落、列表、表格、Mermaid 或语义提示块；未来未知类型同样适用。
- 可用标记：`[!CONTEXT]`、`[!DEFINITION]`、`[!KEY]`、`[!FACT]`、`[!DATA]`、`[!EVIDENCE]`、`[!TIMELINE]`、`[!PROCESS]`、`[!COMPARISON]`、`[!EXAMPLE]`、`[!WARNING]`、`[!ACTION]`、`[!QUOTE]`；确有多人问答才用 `[!DIALOGUE]`。
- 标准写法为引用块，例如：
  `> [!KEY]`
  `> 这里写完整结论及其必要依据。`
- 信息单一的块可以不用提示块；内容较长或结构明显的块通常使用 1-2 个提示块，并让全文累计分散出 4-8 个有信息增量的组件，不要集中在首块或为了凑数量重复结论。不要把每段都包装成卡片。跨块延续同一结构时保持标记一致，不要重新复制前块内容。
- 步骤用有序列表，时间节点用带明确时间的无序列表，真实可比较的列项用表格；Mermaid 每块最多 1 个且不得替代正文。

## 保真要求
- 提示块是正文，不是正文之外的缩略副本。块内完整保留数字、条件、例子、论据、角色归属、转折和限制。
- 详细度 5 下不得为视觉简洁压缩事实；只删除口头禅、寒暄、机械复述和无信息操作。
- 不为了卡片、表格或图形补造事实、角色、时间、数据、关系或结论。
- 原文中的阿拉伯数字、范围、单位、编号和专有名词原则上原样保留（例如 `30年` 不要改成 `三十年`）；相邻时间码把一个长数字切开时按上下文合并，不要四舍五入、改写或省略。
- `ACTION` 只表示原文明确的待办、决策、责任人、期限或操作建议；点赞、关注、投币、订阅、片尾口播、宣传语和泛泛判断不得使用 `ACTION`。
- 按内容类型选择组件：真实多人问答可挑代表性问答链使用 `DIALOGUE`；科普/讲解在有对应证据时使用 `DEFINITION`、`PROCESS`、`EXAMPLE`、`COMPARISON`，不要把所有内容都包装成 `KEY`，也不要强行补组件。
- 长报告若明确包含定义、机制/推导、案例、比较、时间线或步骤，全文至少选择其中 2 种做对应组件，并至少加入 1 处列表、表格或 Mermaid。出现 3 个以上相连阶段、因果节点、概念关系或层级时，优先在最合适的一块给出 1 个简洁 Mermaid，正文仍完整解释。
- 科普/课程同时存在核心概念定义与连续推导链时，分别挑一处使用 `DEFINITION` 和 `PROCESS`；有具体实验、类比或故事时，再选择最有代表性的一处使用 `EXAMPLE`。
- 保持原有 `{{chunk_N_ended}}` 与 `state_ops` 输出协议，报告化标记不得进入 `state_ops`。
